# NEMU RV64 参考模型说明

本文记录 NEMU 在 `CONFIG_RV64=y` 下的实现范围、构建方式和与 NPC DiffTest
的接口约定。RV32 路径保持原有行为。

## 构建

源码仍位于 `src/isa/riscv32/`，由 `CONFIG_RV64` 选择 64 位实现；
`src/isa/filelist.mk` 会把 `GUEST_ISA=riscv64` 映射到该目录。

```bash
cd nemu
export NEMU_HOME=$PWD          # 当前 shell 若已指向别的 NEMU，需要显式覆盖
make riscv64_defconfig
make -j$(nproc)
# 生成 build/riscv64-nemu-interpreter
```

RV32 回归：

```bash
make riscv32_defconfig
make -j$(nproc)
# 生成 build/riscv32-nemu-interpreter
```

作为 NPC 的 DiffTest 参考库：

```bash
make riscv64-ref_defconfig
make -j$(nproc)
# 生成 build/riscv64-nemu-interpreter-so
```

TARGET_AM 构建（要求 `abstract-machine/scripts/riscv64-nemu.mk` 使用
`-march=rv64im... -mabi=lp64`，避免与 klib 的浮点 ABI 冲突）：

```bash
make riscv64-am_defconfig
make ARCH=riscv64-nemu -j$(nproc)
```

## 实现范围

- `RV64I`：64 位 GPR/PC、`LD/SD/LWU`、`ADDIW/ADDW/SUBW`、
  `SLLW/SRLW/SRAW`、`SLLIW/SRLIW/SRAIW`、6 位移位量、完整 64 位
  立即数/分支/跳转、`LB/LH/LW` 符号扩展。
- `RV64M`：64 位 `MUL/MULH/MULHSU/MULHU/DIV/DIVU/REM/REMU`
  以及全部 `*W` 形式；乘高位使用 128 位中间结果。
- `RV64A`（`CONFIG_RISCV_A`，默认 y）：LR/SC 与全部 AMO 的
  `.W/.D`；`misa.A` 置位。xv6 运行配置与回归见 `docs/xv6.md`。
- CSR：`mstatus/mtvec/mepc/mcause/mtval/satp/sepc/scause/stval` 等
  均按 XLEN=64 保存；`misa.MXL=2`；RV64 的 `mstatus.UXL/SXL` 固定为 2。
- 特权/异常：`mret/sret`、M/S 异常委托、向量化中断入口；
  RV64 中断位使用 mcause bit63。
- MMU：Sv39（三级、8B PTE）与 Sv48（四级、8B PTE），支持超级页、
  U/S 权限、SUM/MXR、MPRV、A/D 页错误；未实现的 `satp.MODE` 明确报错。
  RV32 的 Sv32 路径保留。
- PMP：RV64 按 `pmpcfg0/pmpcfg2` 每寄存器 8 项解释；所有表项关闭时
  视为 PMP 未实现并放行，便于与 `HAS_PMP=n` 的 NPC 对齐。
- 工具：ELF64 `readelf`、Capstone RV64 反汇编、ftrace/mtrace/iringbuf、
  SDB 64 位寄存器/表达式与 `x Ng`（8 字节）读取。
- `spike-diff` 导出 `difftest_state_size()`，供 NEMU 在 RV64 下校验 REF ABI。

## DiffTest ABI（RV64）

NEMU 作为 REF 时导出以下固定布局（均为小端、自然对齐）：

```c
typedef struct {
  uint64_t gpr[32];   // x0..x31
  uint64_t pc;
} riscv_difftest_state_t;        // sizeof = 264

typedef struct {
  uint64_t mstatus;
  uint64_t mtvec;
  uint64_t mepc;
  uint64_t mcause;
} riscv_difftest_csr_state_t;    // sizeof = 32
```

导出函数：

- `size_t difftest_state_size(void)` → 264
- `size_t difftest_csr_state_size(void)` → 32
- `void difftest_regcpy(void *dut, bool direction)`
- `void difftest_csrcpy(void *dut, bool direction)`
- `void difftest_memcpy(paddr_t addr, void *buf, size_t n, bool direction)`
- `void difftest_exec(uint64_t n)`
- `void difftest_raise_intr(uint64_t no)`（旧接口，tval 固定为 0）
- `void difftest_trap(uint64_t no, uint64_t epc, uint64_t tval)`
- `void difftest_init(int port)`
- `void difftest_set_platform(int ysyxsoc)`

`difftest_trap()` 是向后兼容的可选扩展（`DIFFTEST_TRAP_ABI_VERSION=1`）：
三个参数固定 64 位，RV32 REF 在内部截断，不改变寄存器快照
（33/264 字节）或 CSR 快照（4 x XLEN）的布局。它在调用
`isa_raise_intr()` 前设置 `isa_trap_tval`，因此 `mcause/mepc/mtval` 或
委托后的 `scause/sepc/stval` 在同一架构边界一起更新；旧接口会显式清空
暂存 tval，避免上一次异常污染下一次。NPC 加载不到该符号时会在启动时
告警并降级为旧接口；若 trap 的 tval 非零则拒绝继续比对。

`paddr_t` 仍为 32 位（NEMU 物理内存窗口小于 4 GiB，默认
`0x80000000 + 0x8000000`）。RV32 布局保持 `uint32_t gpr[32] + uint32_t pc`
和 4 个 32 位 CSR。

### NPC 侧需要配合的改动

当前 `npc/csrc/difftest/difftest.cpp` 在 `CONFIG_XLEN == 64` 时直接拒绝
DiffTest，原因是旧的 REF 状态 ABI 固定为 32 位。接入本 NEMU 时需要：

1. 把 `DifftestCPUState` 的 GPR/PC 改为 64 位，把 `DifftestCSRState`
   的 4 个字段改为 64 位。
2. 删除 `#if CONFIG_XLEN == 64` 的拒绝分支。
3. 继续用 `difftest_state_size()` / `difftest_csr_state_size()` 校验
   字节数（RV64 应为 264 / 32）。
4. 内存同步仍使用 32 位物理地址；镜像与 NEMU 的 `CONFIG_MBASE`
   必须一致（默认 `0x80000000`）。

在 NPC 完成上述改动前，RV64 `--diff` 无法打通；NEMU 侧不会错跑 32 位 ABI：
RV64 加载缺少 `difftest_state_size()` 的旧 REF 会直接 panic。
